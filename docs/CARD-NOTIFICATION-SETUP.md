# 카드 결제 알림 자동 입력 설정

카드를 쓰면 오는 **결제 알림(카톡 알림톡 / 문자)** 을 폰이 자동으로 앱에 보내주고,
앱이 금액·가맹점·날짜를 읽어 **Inbox(검토함)** 에 쌓아주는 기능입니다.

자동으로 확정되지 않습니다. 앱에서 확인 후 "확정"을 눌러야 가계부에 반영됩니다.

```
카드 결제 → 카톡/문자 알림 → 폰 자동화 앱 → 앱 서버 → Inbox → 확정
```

---

## 1. 서버 준비 (한 번만)

### 1-1. DB 테이블 만들기

Supabase → SQL Editor 에서 아래 순서로 실행합니다.

1. `src/db/migrations/054-card-notifications.sql` — 테이블 생성
2. `src/db/migrations/055-card-notifications-alias.sql` — 카드 별칭 컬럼 추가 (토스뱅크용)

### 1-2. 비밀키 등록

폰이 보내는 요청인지 확인하는 열쇠입니다. **이게 없으면 기능이 아예 꺼져 있습니다.**

아무나 못 맞히는 긴 문자열을 하나 정해서 Vercel 에 등록합니다.

| Key | Value |
|---|---|
| `CARD_NOTIFY_SECRET` | 길고 무작위한 문자열 (32자 이상 권장) |

> Vercel → 프로젝트 → Settings → Environment Variables 에 추가한 뒤,
> **Deployments 탭에서 Redeploy 를 눌러야 반영됩니다.**

---

## 2. 폰 설정

무료 자동화 앱 중 하나를 쓰면 됩니다. 둘 다 무료로 충분합니다.

| 앱 | 광고 | 비고 |
|---|---|---|
| **Automate** (LlamaLab) | 없음 | 추천 |
| MacroDroid | 있음 | 무료 매크로 5개 제한 (1개만 쓰면 됨) |

### 2-1. 공통 준비

1. 앱 설치 후 **알림 접근 권한** 허용
2. 폰 설정 → 배터리 → 해당 앱을 **배터리 최적화 제외** (안 하면 절전 중 알림을 놓칩니다)
3. 카카오톡 설정 → 알림 → **메시지 내용 표시 켜기** (내용 숨김이면 읽을 수 없습니다)

### 2-2. 자동화 내용

**트리거 (언제)**
- 알림이 도착했을 때
- 앱: `카카오톡` (문자로 오는 카드는 `메시지` 앱도 추가)
- 조건: 내용에 `승인` 또는 `취소` 포함

> ⚠️ **반드시 발신자/내용 조건을 거세요.** 조건 없이 카카오톡 전체를 보내면
> 개인 대화까지 서버로 넘어갑니다. (서버가 한 번 더 걸러내긴 하지만, 애초에 안 보내는 게 맞습니다.)

**동작 (무엇을)**
- HTTP POST 요청

| 항목 | 값 |
|---|---|
| URL | `https://<앱주소>/api/transactions/notify` |
| 메서드 | `POST` |
| 헤더 | `Content-Type: application/json` |
| 헤더 | `x-notify-secret: <위에서 정한 비밀키>` |
| 본문 | `{"text": "<알림 내용 변수>", "source": "kakao"}` |

`<알림 내용 변수>` 는 앱마다 이름이 다릅니다.
- Automate: `notification_text`
- MacroDroid: `[notification]`

헤더를 못 넣는 경우 URL 뒤에 붙여도 됩니다:
`https://<앱주소>/api/transactions/notify?secret=<비밀키>`

## 3. 서버 응답 읽는 법

| 응답 `status` | 뜻 | 할 일 |
|---|---|---|
| `created` | 거래를 Inbox 에 만들었음 | 앱에서 확정 |
| `duplicate` | 이미 받은 결제 (중복) | 없음 (정상) |
| `unparsed` | 카드 알림은 맞는데 **아직 지원 안 하는 카드사** | 아래 4번 |
| `ignored` | 카드 알림 형식이 아님 (개인 대화 등) | 폰 조건 확인 |
| HTTP 401 | 비밀키 불일치 | 비밀키 확인 |
| HTTP 503 | 서버에 `CARD_NOTIFY_SECRET` 미설정 | 1-2 단계 확인 |

## 4. 지원 카드사 늘리기

현재 규칙이 있는 카드사:

| 카드사 | 규칙 이름 | 형식 | 특이사항 |
|---|---|---|---|
| 삼성카드 | `samsung-v1` | `삼성1810승인 홍*동 / 12,000원 일시불 / 08/08 19:45 가맹점 / 누적...` | 카드 끝 4자리·결제시각 제공 |
| 토스뱅크 | `tossbank-v1` | `[토스뱅크] 체크카드 국내 결제 / 홍*동님의 생활비카드 카드 / 12,000원 결제 \| 가맹점 / 잔액...` | **'승인' 대신 '결제'**, 끝자리 대신 **카드 별칭**, **결제시각 없음** |

> 결제시각을 주지 않는 카드사(토스뱅크)는 같은 날 같은 곳에서 같은 금액을 두 번 결제해도
> 별건으로 인식해야 하므로, 매번 달라지는 **잔액**을 포함한 원문으로 중복을 판별한다.

**규칙이 없는 카드사도 원문은 저장됩니다.** (`status='unparsed'`)
아래 쿼리로 실제 문구를 모은 뒤 `src/lib/card-notification-parser.ts` 의 `RULES` 에 추가하면 됩니다.

```sql
SELECT raw_text, created_at
FROM card_notifications
WHERE status = 'unparsed'
ORDER BY created_at DESC
LIMIT 20;
```

## 5. 안 될 때 확인 순서

1. **아무것도 안 들어온다** → 폰 배터리 최적화 제외했는지, 알림 접근 권한 켰는지
2. **401** → 비밀키가 서버/폰 양쪽에서 정확히 같은지 (앞뒤 공백 주의)
3. **503** → Vercel 에 `CARD_NOTIFY_SECRET` 등록 후 **Redeploy** 했는지
4. **`ignored` 만 온다** → 카톡 알림 내용 표시가 꺼져 있어 내용이 빈 채로 전달됐을 가능성
5. **`unparsed` 로 쌓인다** → 그 카드사 규칙이 아직 없음 (4번 참고)

---

## 6. 개인정보 관련

- 폰에서 **조건에 맞는 알림만** 보내도록 설정하는 것이 1차 방어선입니다.
- 서버는 `금액(원)` 과 `승인/취소` 가 **둘 다** 있는 문장만 받아들이고,
  나머지는 **저장하지 않고 즉시 버립니다** (`ignored`).
- 저장되는 것은 카드 결제 알림 원문뿐이며, `card_notifications` 테이블에 남습니다.
